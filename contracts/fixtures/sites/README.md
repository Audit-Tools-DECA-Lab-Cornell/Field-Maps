# Site fixtures

Sample sites for the collector's site plans (`mobile/src/features/projects/SitePlan.tsx`). The web workspace no longer reads them: it draws the layers of uploaded map packages (`web/src/lib/plan.ts`). Each file is a GeoJSON FeatureCollection in WGS84 (longitude, latitude). They are fixtures: Riverside and the practice garden are fictional, drawn to match the Contour designs, and none of the three is read from or written to the FieldMaps database. A real site arrives as a QGIS map package.

| File | Site | Source |
| --- | --- | --- |
| `riverside.json` | Riverside, three zones | Drawn from System 9 |
| `practice-garden.json` | Practice garden, two training zones | Drawn from the Project 6 thumbnail |
| `fall-creek.json` | Fall Creek, one zone | The collector's QGIS output, combined |

`scripts/site-fixtures.mjs` writes all three. Change the script, not the JSON, then run `node scripts/site-fixtures.mjs`; `--check` fails if a file differs from what the script writes. The files use the same shapes as `parseSite` and `projectSite` in `web/src/lib/plan.ts`.

## Features

Every feature has `properties.kind`, a unique `id`, and optionally `name` and `code`.

| `kind` | Geometry | Other properties |
| --- | --- | --- |
| `site` | Polygon, the site boundary | |
| `grass`, `mulch`, `dirt`, `blacktop`, `path` | Polygon, ground surfaces, drawn in file order (bottom first, as QGIS draws them) | |
| `path` | LineString, a path drawn as a line | `width_m`, its width on the ground |
| `structure` | Polygon, a building | |
| `equipment` | Polygon, play equipment | `source_kind`, the QGIS kind it came from (Fall Creek) |
| `tree` | Point with `radius_m`, or a Polygon crown | `radius_m` |
| `zone` | Polygon, an observation zone | `code` ("A"), `name`; `label_point` [lng, lat] where the name pill sits, when the zone's centre would cover something; `zoom` (Fall Creek's camera hint) |

Colours are not part of a site. The plan takes them from `contracts/map-palettes.json`.

Members beside `features`: `name` (the site's name), `$comment`, and, for a site drawn in plan units, `frame`. Fall Creek also keeps the collector's `source`, `centre`, `bounds` and `aerial` (the drone photo's corners) from `site.json`.

## How Riverside was drawn

Riverside was drawn in plan units first: x runs right (east) and y runs down (south), on a frame 720 × 500 units, which is the extent System 9 shows. In System 9's 1050 px render, one plan unit is 1.46 px. That scale puts North meadow's vertices exactly where Project 9 lists them: (153, 90), (515, 96), (544, 208), (281, 220), (139, 180). Every other shape was traced from System 9 at the same scale. These are the site boundary, grass, mulch (woodland edge), dirt (sand area), the three path branches, the shelter, the play structure, 23 trees and the three zones.

The plan units were then converted to WGS84:

- 0.5 m per unit;
- plan (0, 0) at longitude −76.49800, latitude 42.44400;
- y down is south and x right is east;
- the equirectangular approximation, with 111 320 m per degree of latitude and, for longitude, 111 320 m × cos(42.444°);
- rounded to 7 decimal places (about 1 cm).

The `frame` member records the origin, scale and size, so `toPlan` recovers the plan units the zone editor shows ("5 points · map units") to within rounding. Rings are drawn clockwise on the plan, which makes them counterclockwise in WGS84 as RFC 7946 asks, and zone vertices keep the order Project 9 lists.

The practice garden is drawn the same way at 0.1 m per unit from an origin of −76.48720, 42.44660. It is training geometry and never counts toward coverage.

## Fall Creek

`fall-creek.json` combines `mobile/src/maps/sites/fall-creek/{site,surfaces,equipment,trees}.json` without changing a coordinate. The collector's files are generated by `qgis/fall-creek` from Weronika Kosciolek's QGIS drawings (DECA_FALCR26001); they are not edited here.

- Surfaces keep their kinds, and trees stay polygons.
- Equipment becomes `kind: "equipment"`, with the QGIS kind ("play-structure", "swings", "picnic-table", …) kept in `source_kind`.
- The one zone, "Whole playground" (`zone-a`, code A), is the rectangle from `site.json`'s `zone`, with its `zoom`.

The QGIS drawings have no site boundary, so the file has none. The web fits Fall Creek's plan to its features rather than to a stored frame.
