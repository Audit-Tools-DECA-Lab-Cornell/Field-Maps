05 — Sync

Five states and what moves between them

StateMeans exactlyLeaves whenNever
▣ On deviceCommitted to durable local storage. Survives app close, device restart, flat battery.Connectivity is detected → WaitingDepends on a network having ever existed
◷ WaitingQueued with an operation ID. An attempt is scheduled.Attempt starts → SyncingShown merely because the device is online
◐ SyncingRequest in flight.Ack → Synced · auth failure → On device · transient failure → Waiting with backoff · rejection → Needs attentionDiscards local work on any outcome
✓ SyncedThe server acknowledged this specific revision.A new local edit → On deviceInferred from a successful HTTP status alone
◼ Needs attentionThe server rejected it, or a competing revision was accepted first. The local copy is intact.Resolution is chosen → Waiting, or escalation → stays for the managerResolved automatically by picking a winner
Attempt triggers
  • App launch
  • App resumes from background
  • Connectivity regained
  • Unsent work exists while the app is open
Uploads while the app is closed are not promised. No screen implies otherwise.
Three things the UI keeps apart
  • Connectivity — a radio state, shown in the status bar
  • Synchronisation — a per-record state, shown on the record
  • Package completeness — a per-component state, shown on the project
Conflating any two is the most common failure mode in field tools.
Conflict routing
  • Observer resolves data-entry disagreements: which answer, which count, duplicate placement
  • Manager adjudicates meaning: deletions, zone reassignment, protocol interpretation
Escalated records stay unsent on the device until the manager decides.
06 — Platform notes

React Native / Expo + MapLibre

  • The tablet layout is a real layout, not a scaled phone: a 58 / 42 split with independent scroll regions. Switch on the shortest side, not on a device name.
  • Placement is a map-centre crosshair plus a confirm, or a direct tap — both write the same coordinate. Keep the point draggable with a 44 px handle; the nudge pad is the precision path.
  • Never request location permission to place a point. Ask only when the observer turns the orientation dot on, and keep every other feature working if they decline.
  • The form is one virtualised list of QuestionRow, not nested scroll views. A reveal inserts rows below the current one so the answered question does not move.
  • Write the draft on every answer change and the record in a single transaction before navigating. The receipt screen is rendered from the committed row, not from in-memory state.
  • Bundle the fonts. A field tablet must never show a fallback face because a CDN was unreachable.

Next.js web

  • One filter state owns the map, the table and the export. A filtered export and a filtered view must never disagree.
  • Selection is bidirectional between marker and row, and survives a filter change if the record still matches.
  • Publication is append-only. Persist the full form definition per version; resolve a record's labels through its own version on read.
  • Map package preparation is a server job with per-step results. Surface the failing step and its reason, not a generic error.
  • The QGIS area shows connection details and layer modes. It has no upload action, because uploading is not how the data gets there.
  • Exports carry a codebook and the form version per row. They are labelled supplementary in the interface itself.

08 — Honesty

What the prototypes simulate

Each screen names its own simulation in the panel beside it. The complete list, so nothing is mistaken for working software:

⚠ Maps

A hand-drawn vector site plan, not a georeferenced package. No MapLibre, no CRS handling, no tiles. Coordinates are derived from tap position against an invented origin. Placement, nudging and layer visibility are real interactions on a fake map.

⚠ Download

Progress, byte sizes, the failure at 68% and the four component checks are scripted timers. Nothing is fetched or written to storage.

⚠ Storage

Records live in browser memory for the session. “Force-quit & reopen” re-renders the launch state; it does not prove persistence. The current implementation's SQLite saves are separate from this prototype.

⚠ Sync, auth, conflicts

All front-end states. There is no API, no session, no revision arithmetic. The competing-edit comparison uses invented server values to show the shape of the recovery flow.

⚠ QGIS and database

No PostGIS instance exists. Connection values are illustrative, “Database connected” is a static state, and no export is generated.

⚠ Content

The 64 web observations are generated from a seeded pseudo-random function. Variable codes, labels and rules are read from the workbooks; site names, observers and answer values are fictional.

09 — Open questions

Eleven decisions only the protocol owner can make

Each of these is visible in the prototypes as a flag rather than a guess. None of them are design preferences; each changes what the data means. Cell references are to Sheet1 of the two workbooks — Test is Variables to use for App testing.xlsx, Library is Behavior Mapping Variable Library.xlsx.

01 · blocks the instrument
Do the “if YES” inventory rules mean presence, or a quantity above zero?

Test H19, H21, H23, H25, H27, H29, H31 say “if YES, make the checklist visible”, but the answers are quantity bands with no zero option. As written the condition has no truth value. Either add a presence question, or define the predicate and an explicit none option. The zone-inventory section is withheld from the prototype until this is settled.

02 · blocks export
What is Gender1's export column name?

Test E51 and Library E75 are both blank. The question is selected in the instrument and has no column to write to.

03 · silent data loss if unresolved
Three export column collisions need distinct names

Test E168 and E169 both read Nat_LP_Intn_Binary — natural and manufactured loose-parts interaction. Test E176 and E177 both read Nat_LPs_Lrg — a yes/no answer and its checklist. Test E17 and E199 both read Shade — round climate shade and event-location shade. The prototype shows the last as Shade_Event provisionally; the others are flagged in place.

04 · blocks import
Does “hidden row” mean excluded, optional, or unfinished?

Test rows 33–40 and 180–187 are hidden (16 rows), Library has 12. Test H169 references LooseParts14 and LooseParts16, which are in hidden rows — so a rule points at a question that may not exist. The prototype excludes hidden rows and says so.

05 · changes the schema
Does the second play type get its own subtype storage?

Test rows 83 and 92 define Play_Type_1 and Play_Type_2, but rows 101–133 supply only one subtype set. Library H139 implies both slots need independent storage. The prototype writes Phys_Subtype1 and Phys_Subtype2 — confirm that is the intended shape.

06 · changes round semantics
Does a weather change start a new round, or only affect later events?

Library H28–H36 says climate carries forward until a new first round or a new day. If the weather changes mid-round, either a new round begins or the snapshot is revised for subsequent events only. The prototype snapshots per event, which supports the second reading without committing to it.

07 · blocks several checklists
Which choice lists are still to be provided?

Test G171, G173, G175, G177, G179 and the inventory checklist rows say a list will be supplied. The prototype substitutes the instruction examples and labels each as pending. Alternatively, enable manager-authored lists in project setup — which is a product decision, not a data-entry one.

08 · changes the reveal behaviour
Should “Other” descriptions appear on the option, or on the parent group?

Test H70 and H188 reveal the Other description alongside the whole parent group. The prototype reveals it only when Other is actually selected, which is the more likely intent — confirm, because it changes how many fields an observer sees.

09 · affects analysis
How should multi-select answers be represented in an export?

Coded text in one column, one indicator column per option, a related answer table, or all three. Weather and every checklist depend on this. The export dialog offers indicator columns as an option; the default needs agreeing.

10 · affects zone configuration
Two different definitions share the code EnvZone3

Library B21 and B23 both use it — one for a custom zone ID scheme, one for subzones. They need distinct IDs, with the alternatives preserved as mutually exclusive configuration choices.

11 · affects the whole library import
Are rules present in the Library but absent from the Test sheet inherited or disabled?

The test sheet omits several inheritance and subtype notes that the full library carries. Absence of a note is not a safe execution rule. Also: Test C164 describes a natural feature under the designed and manufactured group — likely a copied label.

Not asked, and not assumed

Nothing in these designs collects participant names, faces, or identifying detail, and there is no live observer tracking. Every example is anonymous. Where the workbook describes a child, the design records only the presenting categories the protocol already defines — age band, presenting gender, group composition — and the clothing-description variable is left unselected in the draft instrument rather than added on our initiative.
